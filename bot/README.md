# Пожарная сводка в Telegram

Бот использует aiogram 3 и Python 3.10 или новее. Из корня проекта создайте виртуальное окружение и установите зависимости.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

Перед запуском задайте переменные окружения `TELEGRAM_BOT_TOKEN` и, для публикаций, `TELEGRAM_CHAT_ID`. В режиме `--dry-run` они не нужны.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `bot/config.py` | Настройки окружения и создание клиента aiogram |
| `bot/interactive.py`, `bot/handlers/` | Запуск long polling и маршруты команд и нажатий кнопок |
| `bot/keyboards.py`, `bot/rendering.py` | Клавиатуры и HTML сообщений |
| `bot/services/` | Чтение сводки для обработчиков и публикация сообщений с учётом лимитов |
| `bot/sources/` | Получение данных BurnBeat, NASA FIRMS и чтение локального JSON |
| `bot/storage.py` | Чтение и сохранение выбора области в JSON |
| `bot/send.py` | Консольные команды рассылки для оркестратора |

Для запуска в виде модулей используйте `python -m bot.send --digest` и `python -m bot.interactive`.

## Публикация реальных данных в «Хакатон»

В zsh выполните:

```zsh
read -rs 'TELEGRAM_BOT_TOKEN?Токен BotFather: '
printf '\n'
export TELEGRAM_BOT_TOKEN TELEGRAM_CHAT_ID='-1004300137252'

python3 bot/send.py --digest
python3 bot/send.py --alerts
```

- `--digest` читает [api/all.json BurnBeat](https://bakai4eg.github.io/fire-free-will/api/all.json) и отправляет один пост по семи областям. Месяц берётся из `data_until`. Сводка показывает месячные числа, норму и сезон. Процент отклонения выводится, если сайт его вернул. Погоду, риск и числа за сутки сайт пока не отдаёт.
- `--alerts` читает открытые выгрузки [NASA FIRMS](https://firms.modaps.eosdis.nasa.gov/active_fire/) и отбирает термоточки за последние 24 часа. Область определяется по границам [geoBoundaries](https://www.geoboundaries.org/api/current/gbOpen/KGZ/ADM1/) (© OpenStreetMap contributors, ODbL). Термоточка — спутниковая отметка, которую нужно проверить на местности. При отсутствии подходящих отметок отправки нет.

Добавьте `--dry-run`, чтобы вывести сообщения. Каждый запуск `--alerts` проверяет своё окно в 24 часа, поэтому при повторном запуске часть отметок может повториться.

## Проверка на тестовых данных

```sh
python3 bot/send.py --digest bot/examples/digest.json --dry-run
python3 bot/send.py --alerts bot/examples/alerts.json --dry-run
```

`--dry-run` выводит HTML в консоль. Пример сводки содержит семь областей в одном сообщении. Пример оповещений выводит одно сообщение о Чуйской области и одно о семи очагах в Ошской. В примерах вымышленные данные и адрес карты `example.org`.

## Подключение другого канала

1. Для демо используйте [@burn_beat_bot](https://t.me/burn_beat_bot). Новый бот создаётся командой `/newbot`. Если токен уже отправляли в переписке, перевыпустите его командой `/revoke`. [@BotFather](https://t.me/BotFather)
2. В закрытом канале «Burn Beat · Тестовый канал» добавьте бота в администраторы с правом публикации. Если поиск ID ничего не покажет, напишите в канале тестовый пост.
3. Введите токен и найдите ID канала. Пример команды для zsh скрывает ввод токена.

   ```zsh
   read -rs 'TELEGRAM_BOT_TOKEN?Токен BotFather: '
   printf '\n'
   export TELEGRAM_BOT_TOKEN
   python3 bot/send.py --discover-chat
   ```

   Команда покажет номер и название канала. Если интерактивный бот уже запущен, остановите его перед поиском ID.

4. Подставьте найденный `chat_id` и отправьте тестовые сообщения. Для публичного канала можно использовать `@username`.

   ```sh
   export TELEGRAM_CHAT_ID='-1001234567890'
   python3 bot/send.py --digest bot/examples/digest.json
   python3 bot/send.py --alerts bot/examples/alerts.json
   ```

5. Откройте канал на телефоне. Проверьте риск с цветными значками, ссылку «Открыть карту», координаты и время по Бишкеку, ссылку Google Maps и сгруппированное сообщение по Ошской области.

## Формат JSON

Сводка принимает объект с `date` в формате `YYYY-MM-DD`, общим `site_url` и массивом `regions`.

| Поле | Значение |
| --- | --- |
| `name` | Название области |
| `risk` | `low`, `medium` или `high` |
| `daily_count`, `monthly_count` | Неотрицательные целые числа |
| `monthly_normal` | Неотрицательная месячная норма, может быть дробной |
| `season`, `reason` | Текст о сезоне и причинах оценки риска |
| `site_url` | Ссылка на карту области. По умолчанию используется общий `site_url` |

Оповещения принимают объект с общим `site_url` и массивом `alerts`.

| Поле | Значение |
| --- | --- |
| `region` | Название области |
| `in_region` | Необязательное название в предложном падеже, например `Ошской области`. Для сгруппированного оповещения берётся из первого очага области |
| `latitude`, `longitude` | Числовые координаты в градусах |
| `detected_at` | Дата и время ISO 8601. Часовой пояс по умолчанию UTC, на выходе время Бишкека |
| `power_mw` | Числовая мощность в МВт |
| `confidence` | `low`, `medium`, `high`, число от 0 до 100 или `null` |

Если в области больше пяти новых очагов, бот отправляет одно оповещение с общим числом и ссылкой `site_url`.

## Интерактивный бот для демо

После подключения запустите на ноутбуке один экземпляр бота. По умолчанию он читает опубликованную сводку BurnBeat.

```sh
python3 bot/interactive.py
```

Откройте личный чат с ботом и отправьте `/start`, чтобы выбрать область. `/today` показывает последнюю опубликованную сводку для неё. Для проверки на локальном файле передайте его путь, например `python3 bot/interactive.py bot/examples/digest.json`. Выбор сохраняется в `bot/state/subscribers.json` между запусками. Кнопка «Отписаться» удаляет сохранённую область. Рассылка запускается отдельно через `send.py`.

## Живая сводка (риск на сегодня)

`send.py --digest` и `/today` теперь собирают сводку на сегодня, а если живой источник недоступен, берут историческую.

- **За сутки** — VIIRS NOAA-20 и NOAA-21 за 24 часа, одна точка на ~1 км (один пожар, увиденный двумя спутниками, считается один раз).
- **За месяц** — только NOAA-20, чтобы сравнивать с нормой BurnBeat (односпутниковый VIIRS; S-NPP больше не публикует NRT). Открытые файлы FIRMS хранят 7 дней, поэтому точки накапливаются в `bot/state/detections.json`; норма пересчитывается на реально покрытые дни («С 8 ноября: …»).
- **Заводы и ТЭЦ** (Кант, Бишкек и др.) отсекаются по маске `api/static_sources.json` с сайта (FIRMS type 2–3 из архива), радиус ~1.5 км.
- **Риск**: сезон (+1/+2), выше нормы >50% (+1), ≥3 очагов за сутки (+1), жара >25 °C, влажность <30%, ветер >30 км/ч (по +1), дождь >2 мм (−2). ≤1 низкий, 2–3 средний, ≥4 высокий. Погода — прогноз Open-Meteo на сегодня по центру области.
- **Оповещения** не повторяются: отправленные точки помнятся 3 дня в `bot/state/seen_alerts.json`.
- **«Выше нормы»**: каждый живой запуск `--alerts` также сравнивает последние 7 дней (VIIRS NOAA-20) в каждой области с обычной неделей этого месяца (медиана 2012–2025 × 7 / дней в месяце) — то же правило, что «Сейчас против нормы» на сайте. Оповещение уходит, если в области не меньше 5 очагов и не меньше чем вдвое больше нормы; повтор не чаще раза в 3 дня, если число не выросло в полтора раза (`bot/state/anomaly_alerts.json`).
- `BURNBEAT_SITE_URL` переопределяет адрес сайта (например, локальный `http://localhost:8000/` для теста).

## Сервер Google Cloud

На VM (Ubuntu) из корня репозитория:

```sh
bash deploy/setup.sh
sudo nano /etc/burnbeat-bot.env      # TELEGRAM_BOT_TOKEN=... и TELEGRAM_CHAT_ID=...
sudo systemctl restart burnbeat-bot
```

Что запускается:

| Юнит | Что делает |
| --- | --- |
| `burnbeat-bot.service` | Интерактивный бот, перезапускается сам |
| `burnbeat-digest.timer` | Сводка в канал каждый день в 08:00 по Бишкеку |
| `burnbeat-alerts.timer` | Проверка новых очагов каждый час в :17 |

Проверка: `systemctl list-timers 'burnbeat-*'`, логи: `journalctl -u burnbeat-bot -f`. Запустить сводку вручную: `sudo systemctl start burnbeat-digest`.
